ACME 旅行社选团助手

门店顾问侧的散拼团销售助手：线路是商品族，团期是变体，ERP 占位是唯一的写操作。五张图分别说明系统架构、两层选团流程、锁位与分享回写、数据模型与映射、占位生命周期，最后是交给 ERP 团队的接口契约。

01 · 系统架构

组件与连接

顾问在工作台里对话，宿主把对话交给 Agent 循环，工具调用落到 TourBackend，再经 ErpClient 协议进入 Mock 或真实 ERP。模型服务通过 Anthropic 兼容接口接入，可换 DeepSeek 或 Kimi。

02 · 业务流 · 两层选团

先选线路，再对团期

顾问用一句话描述客人需求。第一层搜索返回线路（商品族），第二层在一条线路上展开团期（变体），报价按本次人数结构计算。模型只看到 TourBackend 返回的数据，ERP 凭证由宿主持有。

03 · 业务流 · 锁位与分享

占位、满团拒绝、清单回写

锁位是唯一的写操作，购物车只收团期 ID。有位时 ERP 返回带过期时间的占位；满位或已截止时模型只拿到 ID 级别的拒绝，再向顾问报兄弟团期。清单的分享链接由服务端生成，客人在分享页的选择以待处理事件回到顾问的下一轮对话。

04 · 数据模型

ERP 记录如何映射为 Agent 侧类型

左列是 ErpClient 返回的记录，中列是 shopping_agent 核心包定义的类型，右列是 TourBackend 按会话保存的内存状态。核心包零改动：映射全部发生在 TourBackend 内。

05 · 占位生命周期与 ERP 接口

一个团期从报价到占位释放

占位由 ERP 决定过期时间，宿主在每轮对话前把过期通知写入待处理事件。改量是先释放再占位，失败时恢复原占位。下表是交给 ERP 团队的 HTTP 契约与错误码映射。

ErpClient 调用HTTP 契约关键字段错误码 → 异常 → 模型看到的

顺序由后端强制

  • 购物车只接受团期 ID（DP-…），线路 ID 被 gate 与后端两层拦截
  • 搜索结果不足 2 条时按 时段±7天 → 天数±2 → 放弃软条件 三档放宽，并标 match / mismatch
  • 报价按本次人数结构计算，无上下文时如实标注 2大0小

模型只看到数据，不碰凭证

  • ERP Bearer、分享 token、ANTHROPIC_API_KEY 都由宿主持有
  • Unavailable 消息只含 ID，不含中文描述
  • 模型 ID 与接口地址来自环境变量，可换 DeepSeek / Kimi
