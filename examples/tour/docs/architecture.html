ACME 旅行社选团助手

门店顾问侧的散拼团销售助手：线路是商品族，团期是变体，往 ERP 写一张预留订单是唯一的写操作。五张图分别说明系统架构、两层选团流程、写单与分享回写、数据模型与映射、预留订单生命周期，最后是 ErpClient 八个调用与 ERP 端点的对照表。

01 · 系统架构

组件与连接

顾问在工作台里对话，宿主把对话交给 Agent 循环，工具调用落到 TourBackend，再经 ErpClient 协议进入 Mock 或真实 ERP。真实 ERP 用顾问自己的账号登录（只有手机号与密码），读跨该账号被授权的所有部门，写则切到团期所属部门。模型服务通过 Anthropic 兼容接口接入，可换 DeepSeek 或 Kimi。

02 · 业务流 · 两层选团

先选线路，再对团期

顾问用一句话描述客人需求。第一层搜索返回线路（商品族），第二层在一条线路上展开团期（变体），报价按本次人数结构计算。ERP 的团期列表不带价格：市场价要逐条 period/detail 取，顾问结算用的同业价还要在团期所属部门再调一次 order/price，所以一次列表最多取六条团期、线路详情最多十二条。顾问看到的报价是同业价，市场价只留给客人分享页。模型只看到 TourBackend 返回的数据，ERP 凭证由宿主持有。

03 · 业务流 · 写单与分享

写预留单、候补、清单回写

下单是唯一的写操作，购物车只收团期 ID。余位够时 ERP 写一张 预留 订单，购物车行按本地 30 分钟倒计时；余位不足时 ERP 不拒绝，而是写成 候补 订单，该行不占位也不倒计时。ERP 没有取消或改单接口，撤单在 ERP 后台。清单的分享链接由服务端生成，客人在分享页的选择以待处理事件回到顾问的下一轮对话。

04 · 数据模型

ERP 记录如何映射为 Agent 侧类型

左列是 ErpClient 返回的记录，字段名沿用 ERP 自己的驼峰写法；中列是 shopping_agent 核心包定义的类型，右列是 TourBackend 按会话保存的内存状态。核心包零改动：映射全部发生在 TourBackend 内。

05 · 预留订单生命周期与 ERP 接口

一个团期从报价到预留或候补

下单是唯一的写操作。ERP 写下的是一张预留订单，它自己的预留时长由团期的 reserveHours 决定；顾问看到的 30 分钟倒计时是后端本地的。余位不足不是拒绝，而是一张候补订单。下表是 ErpClient 八个调用对应的端点、关键字段与错误码映射。

ERP 没有取消、释放或改单接口。本地计时到期只是购物车行消失，订单仍留在 ERP；取消占位或改人数由顾问在 ERP 后台处理，对话里两者都以中文原因回绝。

ErpClient 调用ERP 端点关键字段错误码 → 异常 → 模型看到的

list_departures(route_id, route_name, …)GET /period/list没有 routeId 过滤：按 routeName 取回，再按 routeId 留下 → availableSeats · planGuests · minGroupSize · confirmCount · reserveHours（不带价格）—
get_departure(period_id)GET /period/detail?periodId=上一行再加 reserveCount · waitlistCount · priceInfo（市场价）；每行都带 companyId404 → ErpNotFound → None
search_customers(keyword)GET /customer/listcustomerId · companyName · csCode · companyType（1 = 同行）—

create_order(OrderRequest)POST /order/createperiodId · customerId · 成人/儿童/老人 · contactName · contactMobile · storeName → orderId · orderStatus · isWaitlist；部门由 token 决定（body 不带），无幂等键，超时先查订单再决定400 → ErpRefused → “Nothing changed: …”
list_orders(statuses)GET /order/list本销售员在登录部门的订单：orderNo · orderStatus · routeName · totalAmount · createTime（其他部门的订单不在列表里）401 / 403 → ErpAuth（先重登一次）
get_order(order_id)GET /order/detail?orderId=上一行再加人数、联系人、departDate 与 reserveExpireAt404 → ErpNotFound → None

八个调用共用一套映射：400 → ErpRefused，401/403 → ErpAuth，404（含裸 nginx 404）→ ErpNotFound，429 → ErpThrottled，5xx、连接失败或读不动的响应体 → ErpUnavailable。前四类由 TourToolExecutor 原样转述 ERP 的中文原因，只有 ErpUnavailable 报成故障。

顺序由后端强制

  • 购物车只收团期 ID（DP-…），线路 ID 被 gate 与后端两层拦截
  • 占位就是 ERP 里的预留订单，30 分钟倒计时是后端本地的
  • 取消与改单在 ERP 后台：对话里 remove 与 update 一律回绝并说明原因

模型只看到数据，不碰凭证

  • ERP 账号密码与 Bearer、分享 token、ANTHROPIC_API_KEY 都由宿主持有
  • ERP 的业务拒绝原样转述给顾问，只有 ErpUnavailable 报成故障
  • 模型 ID 与接口地址来自环境变量，可换 DeepSeek / Kimi
