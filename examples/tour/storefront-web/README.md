# Tour 顾问工作台

同一应用提供旧 ERP 模式与云仓模式。云仓采用三栏顾问工作台，复用原聊天和流式事件。运行时环境变量 `TOUR_BACKEND_MODE` 选择 `legacy` 或 `warehouse`；未配置时保持旧模式，未知值拒绝启动页面。两个模式不共享登录身份或会话编号。

## 云仓模式

平台销售模式由 `/advisor/context` 返回。启用后，页面显示统一货架与统一同行结算价，不要求选择采购旅行社；多个历史工作空间的切换只决定本人记录归属。独立顾问可由管理员开通，后台目录与询价权限不依赖供应商分销授权。旧组织模式仍由服务端明确返回；前端不自行推断或放宽权限。

先启动云仓 API，再从 `examples/` 启动前端：

```bash
TOUR_BACKEND_MODE=warehouse WAREHOUSE_API_INTERNAL_URL=http://127.0.0.1:8005 npm run dev --workspace acme-tour-storefront-web
```

默认端口为 3004。生产构建使用 `npm run build --workspace acme-tour-storefront-web`，启动时带同样的两个环境变量执行 `npm run start --workspace acme-tour-storefront-web`。公网员工访问还需要部署端的 HTTPS、真实平台账号和采购授权。

云仓模式提供：

- 平台邮箱登录、注销及采购组织切换；只展示当前账号具备 `advisor` 或 `buyer_admin` 权限的组织。
- 按名称、出发地和日期查询线路，游标分页读取团期；每条记录显示供应源，未知和过期库存保留明确提示。
- API 线路可显示供应商审批的云仓名称和介绍补充；页面逐项标记来源，不能代替已复核行程。搜索同时识别上游名称与展示名称。报价和客户市场报价保留展示名称来源。
- 在聊天或右侧需求单明确成人、儿童、老人、儿童年龄和房型后，直接点击团期询价。多个方案时不能缺省选择；方案按游标分页，显示服务说明与共享名额提示。浏览器向云仓询价，不计算或拼造供应商价格。
- 市场价与同业采购价分别展示。缺价时总价为待核实，已知部分单列；费用规则、库存、来源时间和有效期可核对，时间使用北京时间。
- 原顾问运行时的线路、团期和报价卡片。界面忽略未完成服务端校验的 `ui_partial` 参数；中断明确提示，未配置模型时目录和直接询价仍可使用。

切换组织或退出后清空已选团期、报价和助手上下文，并取消在途请求。令牌保存在 `localStorage`，读写受限时退回内存；退出时同时清除旧 `sessionStorage`，上游 ERP 凭据只在云仓服务端。聊天在服务端持久化，“我的会话”支持当前用户、当前组织的会话选择、列表分页、历史分页与继续对话；刷新页面后可手动选择原会话。`components/warehouse/History.tsx` 将已提交文本和卡片恢复到原聊天框架，历史报价与库存必须重新核实，不恢复旧快捷操作或未验证的流式片段。授权变化后无法恢复原上下文，应新建会话。

`components/warehouse/` 不调用旧 `/api/login`、购物车、占位、订单或付款接口。`/showcase` 在云仓模式返回 404；旧 `/p/{token}` 显示待迁移提示，不把旧方案编号解释为云仓数据。切换网页本身不会停用另行运行的旧 ERP API；生产切换还需关闭旧路由、迁移历史方案和链接，并完成真实组织灰度验收。

`web-shared/warehouse-client.ts` 与商户端共用身份头、错误处理和 SSE 读取；`warehouse-proxy.ts` 提供同源代理，仅转发必要请求头，禁用缓存和上游重定向。含同业价的页面仅供顾问内部使用，不提供一键导出。

会话栏的“历史档案”由 `LegacyCases.tsx` 提供。每页 25 个已迁入案例，可查看原对话、方案版本、实际父版本、逐日差异及历史参考价；未记录的总额和币种保持未知。选中案例后直接定位详情，重新聚焦或每 30 秒复查权限时保留所选版本，读取失败则清除内容。切换组织或退出会清空档案并取消请求。“核对当前线路”先复查档案授权，再通过明确的来源连接解析旧编号并打开云仓目录。档案不会自动加入助手上下文，不恢复旧报价、分享或编辑能力；真实迁移见[迁移手册](../../../docs/cloud-warehouse/legacy-case-migration.md)。

当前报价的“发给客人”按钮创建对客链接；`ShareHistory.tsx` 保留分享管理与撤销。`CustomerQuote.tsx` 只呈现后端客户白名单；同业价、儿童年龄和库存不进入公开响应。新 `/quote#密钥` 页面通过固定 POST 路径匿名读取，禁用缓存、搜索索引和 Referrer，链接须由顾问自行交付。完整链接只在此次创建后展示，刷新后不能重新取回明文密钥。

导航“报价分享”由 `ShareHistory.tsx` 提供，刷新或重新登录后可查找当前采购组织下自己创建的记录。它与当前报价面板共用分页、状态筛选和明确撤销确认，所有筛选由服务端在分页前执行；切换组织清空旧列表。报价读取权限失效后隐藏原线路与出发信息，自己的分享记录仍可撤销。撤销完成回到当前筛选首页；分享列表不会重现明文密钥。聊天历史卡片分享尚未接通。

查看期限不延长报价有效期，客户页按秒检查本地过期时间，并在重新聚焦及每 30 秒向服务端复查。撤销或权限失效后清除页面报价；历史市场金额不代表当前有效价格，不支持占位、下单或收款。旧 `/p/{token}` 仍保留待迁移提示，不复用新分享密钥。

## 独立浏览器验证

根目录运行以下夹具，只连接 `warehouse_test`，不使用真实 B2B 或模型凭据：

```bash
.venv/bin/python cloud-warehouse/scripts/serve_web_fixture.py --seed-prices --scripted-assistant
```

夹具预置虚构 ACME 线路、托管库存和协议价。`--scripted-assistant` 用固定响应驱动原顾问运行时，工具仍读取测试数据库；这是界面联调，不是模型理解能力或真实供应商验收。省略该参数可验证模型服务缺失时的提示。账号在忽略提交的 `.warehouse/e2e-access.json` 中。

`--seed-legacy-cases` 额外导入 27 个虚构历史案例及各三个方案版本，供档案分页、v3 基于 v1、缺失团队总额、文本转义、当前线路核验和权限撤销验收。夹具归属记录位于私有 `.warehouse/e2e-legacy-cases.json`；授权撤销会改变版本，恢复授权不会重新开放原档案，重新验收应创建新的夹具。

若 3004 已有开发服务，可在本目录用独立端口与构建目录启动：

```bash
TOUR_BACKEND_MODE=warehouse TOUR_NEXT_DIST_DIR=.next-warehouse WAREHOUSE_API_INTERNAL_URL=http://127.0.0.1:8006 npx next dev -p 3006
```

已验证平台登录/注销、线路与团期查询、2 成人的市场价 240 / 同业价 200、缺少老人价格时禁止形成完整总价、切换采购组织清空数据、流式线路/团期/报价卡片、移动端询价抽屉。测试报价前后库存保持 17 位；浏览器业务请求只经过 `/warehouse-api/v1`。

多方案验收在独立 ACME 库完成：商户新增并审批舒适方案和独立价表；顾问对同一团期的两位成人分别询价，基础方案市场价 240 / 结算价 200，舒适方案市场价 360 / 结算价 300，两者可用名额均为 17。方案停用后旧页面再次询价收到 409，原报价卡片清除；切换采购组织清空方案及报价，退出清除令牌，390 像素无横向溢出。该结果不代表真实供应商方案条款已确认。

## 旧 ERP 模式

`TOUR_BACKEND_MODE=legacy` 使用 `LegacyWorkbench.tsx` 和原 ERP 登录、会话、占位等功能；API 地址仍由 `NEXT_PUBLIC_API_URL` 在构建时确定。原演示页位于 `LegacyShowcase.tsx`，仍受 `NEXT_PUBLIC_TOUR_SHOWCASE` 控制。旧模式保留用于迁移对照，不代表云仓具备旧模式的交易能力。


## 顾问需求单工作流

默认打开对话。桌面为 220px 会话栏、对话区、360px 需求单；768px 以下使用会话列表、单屏聊天与底部需求单；768–1023px 为对话和需求单两栏。浏览目录为次级入口，历史档案保持独立。
`BriefPanel.tsx` 支持字段编辑和客人说 / 推断待确认 / 顾问改来源。
报价不再使用独立人数表单；修改报价相关需求后旧报价失效，需要重新询价。
`Workbench.tsx` 的按钮通过持久化 actions 接口操作，不把列表文本当作用户聊天发送。
前端代理须保留 GET、POST、PATCH 三种方法。

“复制给计调”“客人已确认”“线下占位备注”为一期终点；系统未占位。
本次完整验收使用本地 ACME 目录、真实 API/PostgreSQL 和脚本化模型；
详见 [验收记录](../../../docs/cloud-warehouse/advisor-workbench-acceptance.md)。


`mobile.tsx` 提供原生 dialog 底部弹层、键盘视口补偿、持久登录和三级复制回退。
`ResultCards.tsx`、`OfferCards.tsx` 在卡片内追加分页；线路初始展示三条，团期按窗口与日期排序，窗口外数量来自服务器。
`CatalogSearch.tsx`、历史档案和分享记录按需加载。需求中的举例目的地仅参与排序；推断项分别显示在检索和询价准备状态中。
后台恢复每两秒读取当前会话，最长九十秒；服务端仍运行时提示继续等待，不伪造中断。
关闭页面不会保证取消服务器任务，只有服务端终态才确认完成或中断。

微信 openid 绑定登录为后续项。H5 可以复制说明及客户链接，由顾问自行粘贴发送。
小程序 web-view 中不能据此直接调起微信转发；系统分享能力不可用时使用复制。
微信真机键盘、X5/XWeb 流式恢复由用户补充验收；浏览器尺寸模拟不代表真机通过。

云仓默认界面由 `Copilot.tsx` 提供。每份跟单包含沟通、需求与记忆、方案报价、核实跟进四个页签；客户档案独立保存，已有会话可从历史入口恢复。`CopilotBusiness.tsx` 接入商户核实回复、销售报价和人工收款台账；`CopilotCustomer.tsx` 支持补关联客户，`CopilotHistory.tsx` 分页读取完整版本档案。浏览器不保存证件文件或完整分享密钥，原图与识别结果由服务端加密和校验权限。
