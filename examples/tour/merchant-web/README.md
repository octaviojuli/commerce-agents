# Tour 云仓业务工作台

工作台复用原商户端的 `PortalShell`、`AssistantRail` 和中文界面文案，连接独立云仓 API。平台账号决定可访问的供应与采购组织；切换组织会清除页面和助手上下文。采购管理员可提交供应商邀请申请、查看批准结果，以及核对并接受供应商客户映射。浏览器不持有 ERP 接入凭据。

## 启动

先运行云仓服务，再从 `examples/` 启动前端：

```bash
npm install
WAREHOUSE_API_INTERNAL_URL=http://127.0.0.1:8005 npm run dev --workspace tour-warehouse-merchant-web
```

工作台地址为 `http://localhost:3104`。生产构建使用 `npm run build --workspace tour-warehouse-merchant-web`，再用相同服务端环境变量执行 `npm run start --workspace tour-warehouse-merchant-web`。账号通过云仓平台管理流程开通，不使用旧 ERP 登录。

`app/warehouse-api/[...path]/route.ts` 提供同源代理，转发显式 Bearer、组织标识与幂等键，禁用缓存和上游重定向。线路文档上传限 20 MB，其他请求体限 10 MiB，不自动重试业务写入。登录令牌仅保存在当前标签页的 `sessionStorage`，退出或收到 401 后清除。

## 能力

- 线路、团期、订单分别使用 `/routes`、`/departures`、`/orders` 列表及独立详情地址。URL 保存组织、筛选和页码；详情刷新、返回列表、后退／前进和新标签页继续校验登录与权限，列表恢复滚动及记录焦点。
- 线路详情集中展示基础资料、参考价、复核行程、费用须知、图片与原始附件，并复用原有文档及展示补充审批。团期详情分别展示销售规则、原始库存分项与方案价格矩阵；客户协议价仍需采购组织及客户映射，不用通用市场价替代。
- B2B 已有订单采用供应商管理员只读实时查询，供应源必须由运维配置 `order_read_departments`，并与接口账号当前部门权限取交集。每个所选部门完整读取分页后筛选团期和前端分页；失败或超过 25 秒总预算时报错，不返回截断成功。订单详情先验证该 ID 属于当前部门订单列表；父级关联按来源、部门和上游团期 ID 匹配，历史未关联订单仍可读。当前不持久化订单历史、不自动增量同步、不开放交易，也不采集无关联系与游客资料。
- 运维明确配置 `catalog_selection.route_ids` 和 `departure_ids` 后，业务页面和商户目录只展示所选来源 ID。后续同步仍保留完整原始观察，将范围外发布记录持续设为下架，不删除历史、恢复旧状态或增加库存；调整范围须重新审阅和显式处理上下架。
- 团期销售规则：供应商管理员或产品编辑设置云仓停售与北京时间报名截止，提交后在审批中心核对原值、新值和原因，由管理员审批应用。账面余位保持不变；解除限制不等于供应商已确认可报名。审计角色只读。
- 团期报价方案：Excel 来源可新增、编辑或停用多个方案，经统一审批后生效；共享同一团期库存，在价表页面分别定价。API 来源只读。基础目录表格的成人价格仅代表基础方案。
- API 线路展示补充：原始名称和介绍单独展示，可分别沿用上游或填写云仓文案，核对源内容与前后差异后审批应用。后续同步保留补充；恢复沿用采用最新源内容。独立展示版本不使已复核行程失效，旧报价需要重新核价。商户助手的 API 文字修改也使用此审批流程。
- 自管库存查询，销售、总量调整、停售、冲正的提议与完整流水分页。流水按时间及编号倒序，后端判断跨页冲正关联；翻页查找较早业务后可选原流水提议冲正，审批前核对原业务及反向数量。
- 模板下载、中文文件名上传、逐行错误提示、导入发布预览。
- 线路 Word/PDF 原文件上传与鉴权下载、文档历史分页、解析状态、分类失败原因与处理建议、重试、完整行程复核编辑、逐字段修订对照和审批发布。发布版本与解析原稿分开显示，产品版本变化后旧提议不可应用。
- PDF 解析原稿保留封面、逐日段落、费用须知的实际页序，文档页与审批页可打开对应原文件页。页码不替代字段复核；DOCX 与缺少页码的历史稿明确提示下载核对。预览每次通过鉴权读取，关闭、切换组织、卸载或权限复查失败时撤销临时对象 URL；浏览器回焦及每 30 秒复查访问权限。已下载的文件无法远程收回。
- 成功解析的原文件可填写原因重新排队，保留旧解析稿及发布版本；旧未发布提议须根据新稿重新复核。解析历史按次数分页并只读查看，失败重试沿用当前次数。历史产品绑定明确提示不能直接发布到当前版本；审计角色只读，组织切换清除选中稿。
- B2B 来源附件拉取状态、失败原因与重试，自动刷新下载和解析进度；显示最近成功检查、文件是否变化及下次复查计划。详情保留每份文件的系统来源，复查不会自动发布新文件。
- 线路内容修改提议、库存与导入审批，完整核对后才执行批准和应用；只有供应商管理员显示应用操作。
- Excel 来源的采购组织专属协议价维护：市场价与同业价、成人/儿童/老人、单房差、附加费用、房型及年龄条件、费用完整性和有效期。时间明确使用北京时间，缺价保持未知。
- Excel 供应源创建、名称维护和启停；创建须明确确认库存托管责任，不自动向采购方开放，重复提交同一请求不重复建源。系统接口来源显示状态，由接入运维维护。
- 供采邀请创建、一次性邀请码展示、采购预览与明确申请、供应商核对组织后批准或撤销；创建/申请不开放产品，批准才生成分销授权。记录完整分页，邀请码不进入 URL 或浏览器存储，切换组织、刷新和退出清除详情；遗失邀请码须撤销后重建，审计角色只读。
- 已有分销授权的完整分页、供应源及采购组织核对、启用/停用和北京时间有效期维护；管理员明确确认后保存，审计角色只读。
- API 客户代码核验、供应商提议与审批、采购管理员按当前映射版本明确接受；更换版本不能复用旧确认。
- 数据同步页的运行监测每 10 秒汇总同步、库存时效、账本差异、文档处理、检索积压及近 24 小时审批失败；异常含处理建议，监测失败显示上次观测时间，组织切换清除旧组织结果。尚未监测的备份、接口指标和外部通知明确列出。
- 同步错误分类、持久冷却截止提示及统一北京时间；冷却期间人工排队不提前执行。
- 同步异常详情提供来源团期编号、团号、日期和线路关联，区分原始异常与最近成功批次的结果。未返回团期或后续失败不被当成修复；处理步骤引导供应商在原系统修正，再同步核对。页面不提供覆盖来源或强制发布操作，翻页与组织切换清除详情，聚焦及每 30 秒重新校验权限。
- 同步周期、尝试上限、暂停/启用、立即排队与失败重试，均由供应商管理员填写说明并记录审计；配置版本防止覆盖或重复提交。最近后台心跳、成功次数与任务状态每 10 秒更新；排队与执行结果分别呈现。`components/sync.tsx` 提供按来源查看同步历史及异常团期的完整分页。
- 助手会话通过云仓持久化 API 创建、读取与流式输出；可选择已授权采购方查询和提议调整成人同业价。采购方在创建后固定，关闭再打开从服务端恢复；切换采购方须新建会话，清除原对话与价格。未选择采购方时只使用通用查询，协议价未知。
- 助手变更预览展示生成时状态、变更前后值及提议编号，流式事件与历史使用同一去重逻辑。预览是历史记录，实际审批与应用仍须前往审批中心核对。会话恢复失败时禁止续发，允许新建会话；未配置模型显示服务端错误，不回退到演示回复。

协议价与映射审批显示供应源、采购组织和完整业务内容；预览绑定分销授权的编号与版本，授权变更后须重新生成。缺少授权快照的旧预览不能继续应用。系统接口接入、新采购关系开户、多层级及多有效期价表尚未接入；已有分销授权可在工作台维护。真实模型已在 ACME 隔离库验证采购方协议价查询与调价提议，其他聊天卡片、商户长期历史分页及真实供应商模型验收仍待完成。

导入和审批均采用完整游标分页，每页 25 条；待审批状态在服务端分页前筛选，已处理的新记录不会遮住旧待办。翻页及切换筛选清空审批预览，上传和审批成功后返回第一页。目录、库存流水、同步批次及异常记录采用游标翻页，不固定截断于 500 条、20 页或 50 批。库存流水每页 25 条，翻页清空待冲正选择，已经冲正的原记录不再出现在可选列表中。当前应用未切换旧顾问前端，也未部署至 ECS。

## 独立浏览器验收

根目录的 `.warehouse/database.json` 需要已有本机专用数据库配置。

```bash
.venv/bin/python cloud-warehouse/scripts/serve_web_fixture.py
# 需要预置虚构线路以验收协议价与客户映射时：
.venv/bin/python cloud-warehouse/scripts/serve_web_fixture.py --seed-catalog
# API 来源展示补充及恢复上游内容验收：
.venv/bin/python cloud-warehouse/scripts/serve_web_fixture.py --seed-display
# 同时启动虚构供应组织的文档解析 Worker：
.venv/bin/python cloud-warehouse/scripts/serve_web_fixture.py --seed-catalog --document-worker
# 来源附件先模拟失败，再通过工作台重试；不访问外部文件服务器：
.venv/bin/python cloud-warehouse/scripts/serve_web_fixture.py --seed-attachments
# 同步中心验收：61 个历史批次、失败任务及本地虚构目录 Worker：
.venv/bin/python cloud-warehouse/scripts/serve_web_fixture.py --seed-sync
# 库存验收：两个自管库存池，其中一个含 507 条已应用的虚构流水：
.venv/bin/python cloud-warehouse/scripts/serve_web_fixture.py --seed-inventory
# 导入与审批验收：131 次导入，其中较早 31 条待审批、较新 100 条已作废：
.venv/bin/python cloud-warehouse/scripts/serve_web_fixture.py --seed-history
# 模型服务真实调用，业务数据仍为虚构 ACME；不注册真实 ERP 连接：
.venv/bin/python cloud-warehouse/scripts/serve_web_fixture.py --seed-prices --live-model
```

以上命令选择一个。夹具只连接 `warehouse_test`，创建虚构 ACME 供应组织、采购组织、只读隔离组织和账号，监听 `127.0.0.1:8006`。账号和正确/错误 Excel 存放在被忽略的 `.warehouse/` 内，文档原文件保存在 `.warehouse/e2e-objects`；不注册真实 B2B 连接，仅显式选择 `--live-model` 时加载模型配置并消耗调用额度。客户代码 `ACME-CODE` 由进程内虚构适配器核验，不访问上游。前端用 `WAREHOUSE_API_INTERNAL_URL=http://127.0.0.1:8006` 启动即可验收，验收后停止这两个进程。

浏览器验证覆盖：登录、组织切换、中文文件名上传、预览与人工审批、总量 20/已售 2/停售 1 显示余位 17、销售 3 位后余位 14、错误公式文件的行号提示、移动端布局、协议价创建与批准、客户代码核验、供应商审批后采购管理员接受，以及模型未配置错误提示。这些结果来自虚构测试库，不代表真实供应商试点签认。

文档独立夹具验证覆盖：上传三天行程、后台规则解析、修改首日标题、审批前完整修订对照、发布后读取人工版本、原文件字节一致、手机无横向溢出、切换组织清空内容和过期审批禁用。HTTP 同时核对采购方只能读取已发布版本、内部复核说明不外泄、未授权下载拒绝、文档发布后库存保持 17，以及超过 10 MiB 的文档可上传、超过 20 MB 被代理拒绝。

库存夹具验证覆盖：21 页完整遍历、较早销售冲正预览与审批、余位 519 恢复到 522、508 条流水与余额及版本一致、跨页显示已冲正且不可重复选择、另一库存池仍为 17、手机无横向溢出、组织切换清除详情及退出。新增一条冲正记录，原销售和原审批记录保留；这些操作仅在虚构 ACME 测试库执行。

导入与审批夹具验证覆盖：31 条待审批跨两页可查，131 条导入与全部审批跨六页无重复；较早导入完成审批后返回第一页，末页上传新文件后显示新文件。手机布局无横向溢出，隔离组织的导入及审批为空，退出清除工作台，浏览器控制台无错误。全部操作使用虚构 ACME 数据。

PDF 失败提示验收覆盖：三份虚构 ACME 文件分别触发无文字、文字不足和 PDF 读取失败，工作台显示不同处理建议并保留原文件；失败状态无发布入口，重试后原因仍正确，手机宽度 390 像素无横向溢出，组织切换清空详情，退出回到登录页。控制台无错误或警告。

分销授权浏览器验收使用 `--seed-catalog` 夹具：供应商管理员停用 Excel 来源授权后，采购方可查询产品从 2 条变为 0 条；明确确认恢复并设置结束时间后恢复为 2 条，授权版本为 3，北京时间输入与后端 UTC 一致。未确认不能提交，手机无横向溢出，组织切换清除详情，审计角色仅能查看，退出回到登录页，控制台无错误或警告。

供应源浏览器验收使用 `--seed-catalog` 夹具：管理员确认托管责任后创建 Excel 来源，导入页立即可选并成功上传；更名与启停后，来源仅在启用时出现在导入选项中。独立 API 核对一个有效导入批次及零自动分销授权。手机无横向溢出，隔离组织看不到来源，审计角色无创建入口，退出与控制台检查通过。

助手采购上下文验收使用 `--seed-prices --live-model`：选择采购方后读到成人同业价 100 元，生成 110 元待审批提议；收起再打开恢复同一采购方和变更对照，重复事件只显示一个预览。新建通用会话清空旧内容，重新查询价格为未知。数据库核对两个会话分别绑定指定采购方和空上下文，提议未批准/应用，实际协议价仍为 100 元、两个团期余位仍为 17。390 像素手机无横向溢出，切换隔离组织清空对话且不出现原采购方，退出及控制台零错误零警告检查通过。

销售规则浏览器验收使用 `--seed-prices`：ACME 团期设置停售及北京时间截止，审批中心展示原值、新值、团期和原因；确认应用后商户显示停售、顾问询价按钮禁用，账面余位仍为 17。刷新后截止时间恢复一致，手机宽度 390 像素无横向溢出，两端切换隔离组织后清空原内容，退出及控制台零错误零警告检查通过。上游自身的停售和报名截止字段尚未映射。

Excel 版本 2 支持批量停售、北京时间报名截止与规则说明。审批表格逐行展示实际规则的原值、新值、时区和原因；空白保留，清空截止用“清空”。ACME 浏览器验证模板上传、预览、审批和目录显示；总量 20、期初已售 3、期初不可售 2 保持账面余位 15，整体停售不扣库存。旧 10 列模板继续接受。

“价表与等级”按团期维护标准价、等级价和采购协议价，支持多个不重叠有效期、修改与停用。采购等级按供应源分配，对该来源全部 Excel 团期生效。界面按询价时刻采用完整价表，不混合不同层级金额；审批中心呈现原值、新值、完整费用、有效期及适用对象。产品编辑可提议价表，等级分配和应用由供应商管理员完成；API 来源显示上游价格说明。

分层价表验收使用 `--seed-prices` 的独立 ACME 库，浏览器完成标准价、等级价、等级分配及协议价/等级停用审批。HTTP 核对成人结算价按协议 100 → 等级 130 → 标准 150 切换，旧报价失效，库存一直为 17；刷新、手机布局、组织隔离、退出与控制台检查通过。

线路详情用 `components/route-itinerary.tsx` 展示概览、逐日导航、景点、三餐、住宿和独立费用规则。优先展示审核发布版本；无发布版本时，有文档权限的商户可预览最新成功解析稿，明确标注待复核及版本差异，不向采购方开放，也不自动发布。

B2B 团期首次进入自动查询库存与市场价，手动刷新失败会清除即时结果。管理员输入 B2B 客户编码、核对名称并确认后读取该客户的同行结算价，复用 15 分钟客户核验，不建立采购绑定。接口价格类型必须明确为同行价、同业价或结算价；零值、缺失和读取失败分别呈现。Excel 来源仍使用已发布价表，导入页提供模板字段与独立价格、行程维护指引。

## 线路内容工作台

`components/route-editor.tsx` 按天编辑简述、分段安排、三餐和住宿，原文件按需读取。保存写入云仓草稿，提交后在原审批中心核对发布；客户预览只读取服务端生成的已发布内容白名单。线路标签可新增、修改、移除及确认上游候选，审批后用于检索。原文件和旧修订保留，重新解析不会覆盖人工内容或自动发布。

团期详情首次进入自动读取库存与统一同行结算价；统一价的查询身份由供应源运维配置，页面无需选择采购客户。

## 结构化行程的逐项确认

结构化行程（`route-kit/1`）默认进入“审核”页，由 `components/route-kit-review.tsx` 逐项提问。`lib/route-review.ts` 把云仓返回的待确认事项和解析证据（`quality.issues`、`units`）转成问题卡片：一句白话问题、原文出处，以及可点选的答案，例如“原文没写，保持未说明”“原文写了：入内参观”“确认不要”“原文有，加回”。每个答案只对内容做幂等的写入，可随时改选。

- 答案写入内容后，提交时先校验取得当前内容的 `basis_hash`，再由所选答案生成 `review_resolutions`（处理说明自动生成），保存并发起发布。供应商管理员一次点击完成提议、批准和应用；产品编辑只提交审批。
- 解析器为节点级问题附带 `subject`（节点名称），因为问题路径中的序号指向模型输出的原始列表，不是保留下来的列表；缺少 `subject` 的旧稿按“无法定位”处理，只能保持现状或转到高级编辑。
- 需要改字段才能解决的事项（如费用包含与不含冲突）显示“去修改这一处”，进入高级编辑；改完回到审核页“重新检查”。
- 行程与线路登记的天数、出发口岸不一致时，审核页给出“取舍卡”：并列显示标题、上游登记、团期日期跨度和附件行程，可选“以行程为准（云仓核定，上游不改）”或回到高级编辑改行程；口岸另可选“两者都对”。核定随草稿保存并在发布时生效，线路列表标注“云仓核定”。
- 线路列表上方的“上游数据待更正”列出仍在生效的核定，可复制成表格交给上游更正。
- 旧结构的线路仍使用下面的按天编辑与逐日事实核对。

## 逐日事实核对

`components/route-fact-review.tsx` 展示私有候选稿的逐日核对记录。默认只看保留原文的项目，可展开对象、原声明和未采用的改写，并定位当天原稿。通过仅表示规则及模型未发现问题，不替代人工业务审核。客户投影不包含这些报告。
