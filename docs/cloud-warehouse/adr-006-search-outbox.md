# ADR-006：可重建检索与数据库 Outbox 消费

## 决策

一期使用 PostgreSQL 内的 `product_search`，索引线路有效名称、来源名称、线路代码、出发地。价格、库存、销售状态、授权均不进入检索副本，查询结果仍从当前业务表取值。中文按字面子串匹配，不声称具备中文分词、目的地推断或语义检索。

`product_search_v1` 按供应组织消费 Outbox，一批最多 50 个事件。需要刷新时同批只扫描一次该组织线路，按来源版本、展示版本及文本差异更新。全量刷新适合一期目录规模；大供应商应改成携带产品编号的增量事件，再按真实容量评估分区或独立搜索服务。

`search.py` 统一顾问与商户的匹配规则。索引版本落后或记录缺失时，当次请求回查当前文本；旧名称不会因为旧索引继续命中。名称展示补充后仍可用来源名称查找。搜索中的 `%`、`_`、`!` 均作为文字处理。商户 Agent 先在数据库筛选匹配线路，再加载这些线路的团期；价格/库存排序仍可能读取全部匹配团期，容量工作未宣称完成。

匹配直接使用已关联产品的当前检索副本或实时文本，避免额外扫描整个授权目录的子查询。迁移 `0023_catalog_scope` 将产品/团期的采购连接授权集合在每条语句中读取一次，保留采购成员、用户、组织、供应组织、来源启用、授权启用及有效期检查；供应商仍可读自己的非发布记录。函数没有可指定其他采购组织的参数，固定搜索路径，默认不向 PUBLIC 开放执行。没有跨语句或跨事务权限缓存；同一连接下一条语句立即遵循已提交的授权撤销。

## 权限与一致性

检索表强制 RLS，通过实时 `supplier_product` 可见性过滤。每次查询再关联实时产品表；来源停用、授权撤销、产品归档立即生效，无需等事件消费。索引没有授权缓存。副本写入仅允许所属组织的 `sync_worker`，采购方和供应商业务角色不能修改副本。

每个事件、消费者版本只有一条 `outbox_receipt`。检索更新及成功回执在同一事务提交，进程中断全部回滚。重复运行不再次处理成功事件。`outbox_event.processed_at` 保留原值，不将一个消费者完成错误地理解为所有消费者均已完成。未来增加消费者必须使用独立名称和回执。

消费者只执行数据库操作，采用组织级事务咨询锁及 `FOR UPDATE SKIP LOCKED`；锁随连接终止自动释放。此处没有事务外的网络操作，因此无需复制同步 Worker 的跨事务租约。涉及外部系统的未来消费者必须另设租约、幂等调用和未知结果回查，不得复用此方案承诺外部恰好一次。

## 失败与恢复

刷新在保存点内执行，数据库错误回滚本次刷新，回执记录固定错误码和指数退避，默认最多 5 次。耗尽后进入 failed；运维显式重试增加 5 次预算并写审计，累计尝试次数不清零。未知事件立即失败，不能静默丢弃。明确不影响检索的事件记录 ignored；库存、权限、价格的即时生效仍由业务查询负责。

`warehouse outbox-status` 和鉴权的 `GET /v1/search-worker` 返回组织内积压、失败、最早待处理时间、最近心跳、心跳是否超过 30 秒，以及副本当前/缺失/落后数量。这里只提供可观察状态，尚未接外部告警通知。失败详情最多返回 100 条，总数另列。

`warehouse rebuild-search` 从业务表重建所属组织副本，不修改产品、库存或回执。需要恢复某个失败事件时使用 `warehouse retry-outbox --event UUID`。所有命令使用受限 runtime 数据库角色及明确的组织/Worker 身份。

## 复用与性能边界

复用 PostgreSQL 的 [pg_trgm](https://www.postgresql.org/docs/16/pgtrgm.html) 和 [SKIP LOCKED](https://www.postgresql.org/docs/16/sql-select.html)。`pg_trgm` 可支持子串检索索引；短关键词、RLS 和实时回退可能限制索引收益，不能仅凭创建 GIN 索引宣称达到容量目标。须在真实权限上下文中查看执行计划、测量延迟。迁移角色安装扩展，运行角色不获得安装权限。

没有引入 Kafka、Elasticsearch 或额外的分布式服务。索引可重建，事实和权限保留在云仓业务表中。

基线执行方法与实测限制见 [容量验证](capacity-report.md)。当前查询形态不承诺使用 GIN；是否采用索引以受限运行身份下的执行计划为准。
