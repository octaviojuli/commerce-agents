# ADR-009：复用授权查询的执行计划

状态：代码与隔离数据库回归通过，已部署至杭州 ECS；小规模目标通过，规划长负载时延仍未达标。性能和发布证据见容量与部署记录。

## 问题

ECS 大目录 400 次 HTTP 诊断请求中，采购连接函数调用约 5,300 次，组织校验约 10,000 次。统计显示嵌套授权 SQL 的重复规划成本显著；这些统计包含预热与分析开销，嵌套计时重叠，不能相加当作请求总耗时。认证入口本身不是本轮主要热点。

## 决策

迁移 `0031_authorization_plans` 将既有四个函数改为 PL/pgSQL 静态参数化语句：`warehouse_has_org`、`warehouse_has_role`、`warehouse_buyer_connections`、`warehouse_live_grant`。查询条件保持一致，表和函数使用 `public` 限定。PL/pgSQL 使用 PostgreSQL 的预备语句机制复用解析和可复用的执行计划；不会将授权结果保存在应用缓存、连接变量或临时表中。[PostgreSQL 16 执行计划说明](https://www.postgresql.org/docs/16/plpgsql-implementation.html#PLPGSQL-PLAN-CACHING)

原有 `STABLE` 属性不变，每条业务语句使用其当前数据库快照；默认 READ COMMITTED 下，下一语句仍能看到已提交撤权。时间条件继续调用 `now()`，没有将时间文字转成连接生命周期内的常量。

组织、角色和采购连接函数保留原 `SECURITY DEFINER` 与固定 `search_path=public,pg_temp`；有效授权函数保留 `SECURITY INVOKER`，仍经过运行角色和表 RLS。`CREATE OR REPLACE` 不创建新的权限入口，保留函数所有者、签名及 ACL。没有减少报价保存前的版本复核或保存后的权限读取，没有修改写策略、价格或库存。

## 验证与发布

完整隔离数据库与连接器回归 445 项通过；后续连接池、同步和价格专项 60 项通过。新增测试把池限制为一个物理连接，连续切换组织预热 24 段事务后修改角色和供采授权，验证下一语句立即拒绝，并验证提交后没有残留身份或访问权限。

上线前需要备份、安装新迁移并核对函数权限；旧应用可使用同一签名。回退函数语言时使用该迁移的 downgrade，保留相同查询条件；实际业务数据恢复仍须按成套恢复手册执行，不能覆盖正在运行的数据卷。

性能比较使用同一 Linux 镜像基础、数据库资源上限、目录规模、并发和时延目标，保留失败样本。函数规划减少不自动代表全部容量通过，最终结果见[容量报告](capacity-report.md)。
