# 顾问搭档第三版修复复测记录

**测试对象**：Codex 分支 `codex/advisor-fixes-v3`（HEAD `8cbfdcc`），含工作区中尚未提交的改动（41 个文件，+4801/−547），测试前已整体复制成快照，Codex 的工作区没有改动。

**测试环境**：两套，都用真实模型。
- **A**：本地云仓目录的克隆库。30 条真实线路，但没有已发布行程和价格。
- **B**：Codex 的 ACME 验收夹具。5 条虚构线路，含行程、统一价和儿童占床价。

从“客人的问题”开始的后半段故事线只能在 B 上跑。

## 结论

- **程序控制部分基本达标**：F2、F3、F4、U1、U2、U6 通过；F7 大部分通过。
- **模型撰写的草稿没有达标**，这是 F1 的核心，也是顾问每轮都会直接感受到的：
  - 草稿收不到已保存的需求，于是几乎每轮都重新问客人“几位大人几位小孩、孩子几岁、什么时候出发”；
  - 校验器又把带事实的句子大量删掉，草稿里剩下的只有追问。
- 按故事线计，14 步中 6 步通过、4 步部分通过、4 步不通过。

## 交给 Codex 的剩余问题（按优先级）

### P0
1. **草稿拿不到需求**：`warehouse_copilot.py` 调用 `draft` 时没有传已保存的需求单。要求：
   - 传入需求摘要（已知项、待补项）、当前线路和团期、报价摘要（客人价，不含同业价）；
   - 提示词写明“已知项不再追问”；
   - 校验器把“追问已知项”也算作违规。
2. **校验器过严**：
   - 删句的判断依据 `FACTUAL` 过宽，“出发”“安排”“酒店”这样的词一出现就要求引用；
   - `supported()` 要求引用文字逐字出现在事实里，模型改写一个字就失败，每轮 5–11 个“无依据”。
   - 要求：
     - 事实可以按短语匹配，只核对数字、日期、否定词和限制条件；
     - 衔接句、复述客人原话的句子不做事实校验；
     - 每轮删句率进入指标，目标 < 20%。
3. **需求对接轮被整轮判为降级**：只有部分字段校验失败时，保留有效字段，正常撰写草稿，页面上只提示哪个字段没理解。偏好的提取要能把“别太累、最怕行程太赶”写成 `slow_pace`，并记入客人记忆的顾虑。
4. **对线路的提问被当成需求变化**（在 A 上出现）：“XX 那条会不会很赶”这类问话，不能改写目的地。依据如果是整句原话，就拒绝这项变化。
5. **儿童占床要逐个孩子记录**：`child_bed` 改为按孩子记录，例如 `[{age:5, bed:false}, {age:8, bed:true}]`，计价时分别取占床价和不占床价。

### P1
6. 变更采纳后，未处理的项不应阻断找线；选定团期后，聊天里仍允许重新找线。
7. 方向卡：
   - 去掉“综合经典”这类兜底方向；
   - 有价格的线路给出价格区间；
   - 草稿要介绍这 2–3 个方向，而不是重复追问。
8. 行程事实：
   - 过滤空标签（“政策：”“材料要求：”“单房差：”）；
   - 普通的某天行程不列为“缺点”。
9. 界面：
   - 按钮操作在对话里显示为“顾问操作”，不标“客人 · 从微信粘贴”；
   - 状态条文字跟随阶段更新；
   - 线路标题去掉编号前缀；
   - 需求单改为紧凑标签，空项合并成一行“还没提：…”；
   - 已成交的单子退出待办；
   - 草稿里的称呼出现“您您好”，需要修正。

### 复测标准（Codex 修完后）

- 同一条故事线跑 3 遍，满足以下全部条件：
  - 草稿追问已知信息的次数为 0；
  - 问餐食、价格时，草稿直接给出答案；
  - 需求对接轮不降级；
  - 5 岁孩子按不占床计价。
- 自动检查中增加一条：草稿问句不能涉及已保存的字段。
