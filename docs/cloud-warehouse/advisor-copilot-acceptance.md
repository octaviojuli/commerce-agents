## 验收结果

| 场景 | 结果与证据 |
|---|---|
| 真实目录选线 | 首次展示候选线路，不自动选线或提前列出团期；明确选择后再看团期和方案 |

| 商户闭环 | 顾问页面提交核实，商户页面人工回复，顾问采纳；后续连续两轮答疑引用本单回复，保留酒店最终确认与不能保证的条件 |
| 无依据的承诺 | 未确认退改、购物与自费事项保持待核实，不承诺全退或无购物 |
| 私有资料 | 10,850,629 字节虚构 PDF 通过公网上传；下载哈希一致；服务器文件为 AES-GCM 密文；识别结果待人工处理，不自动创建旅客 |
| 角色与访问边界 | 公网商户读取顾问私有跟单、附件被拒绝；顾问冒充商户回复被拒绝；匿名访问被拒绝 |
| 持久化与恢复 | API 替换并重启后，客户关联、会话、商户回复、材料仍可恢复；材料继续使用原密钥解密 |
| H5 | 实际页面 375 像素视口，文档宽度同为 375，无横向溢出；刷新后可恢复跟单 |

最终公网修复复验包含三组场景中的六轮 HTTP 模型对话，以及真实页面上的两轮连续答疑。此前选线、选团期、询价、模糊需求和商户双向沟通另有回读记录。每轮成功回复均检查了实际输出，不能以收到 HTTP 200 代替业务通过。

验收过程中发现并修正了三处问题：网页代理与材料页上传大小不一致；历史未采纳聊天干扰当前字段提取；房型输出允许无类型值，导致空数量拒绝整轮需求。最终提取只读取已存需求和本轮原话，房型使用结构化类型；识别为调整却返回空变更时重试并明确提示。

## 业务与验收边界

真实上游样本返回两位成人的已知结算部分为 CNY 21,398，费用完整性与所选房型仍未确认。系统展示缺项并拦截正式销售报价，不将已知部分改称全包总价，也不根据自由文本回复补造价格。正式报价、利润及线下成交完整流程已用虚构完整价格验证；该真实样本仍需要商户或上游提供完整条件。

通用结算身份继续由服务端配置，不引入顾问差异价。跨顾问客户、附件、报价与台账隔离由真实 PostgreSQL 隔离测试覆盖。新增公网临时顾问账号被自动审批拒绝，原因是账号主体、权限及生命周期没有得到明确授权；未绕过限制，因此没有把现有账号的组织边界检查写成双顾问公网验收。

窄屏浏览器验收不等于微信真机验收。部署原有测试发布模式保持原样；机器生成的行程不被标成人工审核事实。
