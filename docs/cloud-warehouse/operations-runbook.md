# 云仓运行监测

## 入口与覆盖

供应商管理员或审计员登录商户工作台，打开“数据同步”的“运行监测”。页面每 10 秒读取所属组织的 `GET /v1/operations`。运维可以使用受限 runtime 身份执行 `warehouse operations --organization UUID --user UUID`。接口无业务写入，不自动修复或向外发送消息。

结果包含观测时间、当前异常及处理建议、24 小时同步成功/完成次数、库存和账本统计、文档和检索状态。供应源名用于定位；不会返回连接凭据、模型输入或数据库错误原文。采购方与产品编辑员不能读取运维接口。数据库 RLS 仍约束每项查询。

“已监测项目未发现异常”只代表所列监测项目。备份/异地副本、接口时延/报价成功率和外部通知投递暂未集中接入，页面明确显示未监测。浏览器关闭后不会主动通知员工。生产需继续接入监控采集器、通知接收人及备份结果上报。

## 判定与处置

| 信号 | 判定 | 处理 |
|---|---|---|
| 未配置持续同步 | 有效 API 目录源没有同步任务 | 配置该组织 Worker 和任务；一次手动同步不等于持续更新 |
| 同步暂停 | 任务被显式禁用 | 作为信息提示；不报该任务心跳/同步陈旧告警，库存时效仍如实计算 |
| 目录心跳缺失 | 已启用任务没有心跳或超过 90 秒 | 核对进程、数据库、组织成员与 Worker 归属 |
| 同步租约过期 | 运行任务的租约到期 | 核对中断原因，允许持有有效新租约的 Worker 接管；不清零已消耗次数 |
| 调度停止 | 任务处于 failed | 核对固定错误码，修复后在工作台明确重试 |
| 来源鉴权失败 | 最近批次或任务记录鉴权/权限失败 | 接入管理员核对供应商凭据和权限；界面不接收或显示密码 |
| 同步陈旧 | 从未成功，或距最近成功超过 max(900 秒, 3×任务间隔) | 核对调度、供应商可用性和持久冷却；冷却不让旧库存变成新数据 |
| 来源隔离记录 | 最新成功批次有未关联等异常 | 打开批次异常详情，由供应商修正后重新同步；不自动补造线路关联 |
| 外部库存过期 | 有效来源的未来已发布团期快照到期 | 页面继续显示过期/未知；外部库存快照不代表云仓托管余额 |
| 账本差异 | total/sold/blocked/held/版本与全部流水不一致 | 人工暂停相关业务核对；不得直接覆盖余额或抹除流水 |
| 检索心跳缺失 | 有产品或积压，心跳缺失或超过 30 秒 | 核对检索 Worker；查询版本校验与实时回退继续生效 |
| 检索积压 | 待处理事件最早等待超过 5 秒 | 核对消费者和数据库吞吐；副本不是价格、库存或权限权威 |
| 文档失败 | 当前产品版本原文件拉取或解析失败 | 核对错误类型、受控主机、文件格式；人工补充或显式重试 |
| 审批/库存拒绝 | 近 24 小时已审批操作出现冲突、库存不足或重复编号 | 按变更状态及库存流水复核；同一成功请求重放不属于重复扣减异常 |
| 审批数据库错误 | 近 24 小时已审批调用返回数据库异常 | 先查询变更状态和业务流水，再判断提交结果；断连可能发生在提交响应阶段 |

默认阈值是当前运行基线，尚未供应商级配置或压测校准。停止的来源不参与同步健康判定；已过出发日期的团期不参与未来库存时效统计。文档待复核按文件计数，一条线路可能有多个待复核文件。监测查询并非同一冻结快照，连续写入时各类统计可能短暂不同步；不能用监测页面替代业务事务校验。

## 失败记录边界

业务调用结束后，`changes.apply` 对冲突和数据库异常尝试另开事务写入不可变审计 `change.apply_failed`。只记录当前组织内、由当前审批人审批的变更；字段为固定错误码、变更类型、变更编号、操作人和时间，不复制 payload 或异常原文。原调用的异常不被监测记录替换，记录失败时只输出固定日志码 `WAREHOUSE_OPERATION_OBSERVATION_FAILED`。

版本/业务冲突的事务会回滚。数据库异常本身不能证明提交没有完成，尤其是提交阶段断连；应通过同一 change_id 查询结果，成功重放返回原结果。监测保存近 24 小时错误统计，即使后来已经人工解决仍保留该时间窗的记录，不能把统计当成未结工单数量。

没有新建业务写入入口或自动补库存，也没有修改真实供应商凭据。ECS 持续运行和告警通知须在明确部署目标及通知接收人后验收。
