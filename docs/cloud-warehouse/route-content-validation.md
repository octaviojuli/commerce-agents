# 线路内容优化与验证

## 数据路径

API 提供线路身份、名称及标签，附件提供带证据的行程候选。DOCX 直接提取段落和表格；PDF 保留原文件、物理页定位后分日，转换成 `RouteDoc` 2.0。每日标题、简述、有类型的段落、三餐、住宿和费用字段保存到云仓数据库。原文件、原解析、人工修订、审批发布各自留存；不回写 B2B。

Markdown 是可读中间稿，不能代替结构化字段和原始证据。若采用 MinerU，应同时保留 Markdown、结构 JSON 和真实页定位，并对同一文件逐项核对跨页分日、餐住、航班、自费/外观/替代条件、费用与须知。只因 Markdown 更整齐，不能认定更准确。图片封面中的内容仍需 OCR 或人工核对；本轮规则不会猜测图中文字。

## 原文件抽样

同一原文件的前后解析结果：

| 样本 | 格式 | 旧解析日条目 | 新解析日条目 | 标称天数 |
|---|---|---:|---:|---:|
| 阳光西葡 | PDF | 2 | 13 | 13 |
| 东航西欧 | DOCX | 12 | 12 | 12 |
| 西葡线路 | DOCX | 12 | 12 | 12 |

PDF 修复了居中天号导致首日内容错位、跨页续行、自费推荐误截断后续团日、数字航司代码漏读和返程到家误算酒店。逐日段落保留原文限制条件；外观/入内不单独决定是否含门票。正文之外的须知不再静默截到前 40 项。天数与结构检查通过仍不等于所有承诺均已人工核实；正式发布沿用人工审批。

有效凭证下已完成一份 PDF、两份 DOCX 的 MinerU 同文件对照。PDF 补出了图片封面中的酒店标准和航司；当前适配得到的逐日条目少于原生解析，混合方案保留原生 13 天正文。两份 DOCX 的本次原始输出缺少逐日参考航班，因此默认继续原生解析。完整结果、共用 Skill 和自动处理边界见 [MinerU 与 Skill](mineru-skill.md)。官方协议参照 [MinerU API 文档](https://mineru.net/apiManage/docs)；输出格式见 [官方文档](https://opendatalab.github.io/MinerU/reference/output_files/)。

## 实现边界

- 编辑草稿、按日核对简述、版本冲突检查、来源变更检查、原文对照和发布审批写入云仓；重新解析不自动审核。
- 标签的候选、确认与排除独立保存；已确认可检索标签用于现有顾问搜索。
- 客户预览仅返回已发布内容白名单，隐藏内部来源、采购结算价、具体库存与审计身份；目前不是新增的匿名客户分享地址。
- 国旅环球统一结算价使用供应源配置的标准上游查询身份。商户不再选择采购客户，顾问采用同一价格依据；缺失儿童/老人价不按零价发布。
- 原文按需加载，进入线路详情只读取云仓数据，不等待供应商接口或重新解析。

## 上线验收

部署保留原先 30 条线路、200 个团期的展示范围。29 条有附件的线路已完成新版解析并写入候选，1 条缺少附件；均未自动审批为对客正式行程。Linux 使用同一 SHA-256 的阳光西葡 PDF 得到 13 天、70 个内容块，并保留物理页定位。镜像补齐公共解析模块与标签规则文件，容器验收实际调用受限解析子进程，避免只测试文件上传。

线路界面验收时 API 为 `local/warehouse-api:20260926-03`，商户网页为 `local/warehouse-merchant:20260926-01`，数据库为 `0033_route_content`。后续 MinerU 接入已升级为 API `20260926-05` 与数据库 `0034_document_extraction`，见 [共用 Skill 与上线验证](mineru-skill.md)。升级前备份验证覆盖 44 张数据表和 425 个私有原文件。公网商户团期页面已验证自动读取成人同行结算价 12,700 元。

相关回归共 599 项通过、零跳过，另通过代码检查、两端 TypeScript 检查、商户生产构建及 Linux 容器验收。虚构数据浏览器已走通内容编辑、保存、发布审批、客户预览和标签审批；公网读取验证商户与顾问使用同一成人结算单价。顾问完整报价仍因上游费用未完整确认而保持不完整，已知结算小计为 12,700 元；精确库存未向顾问返回。最终实测一次已登录内容接口为 0.065 秒，该数值不代表首次登录或完整首屏耗时。
