# 顾问搭档一期实施与验收

## 业务范围

顾问独立管理客户、出行人、跟单、方案、报价及线下成交台账。商户仅接收顾问明确提交的核实单，回复后由顾问采纳。通用上游询价身份提供统一结算价，不按顾问区分结算价格。销售价默认采用市场价，顾问可修改；低于结算价需要显式确认。利润等于同币种、同费用口径的销售总额减结算总额。占位、下单、支付接口继续关闭。

业务数据持久化到云仓 PostgreSQL；私有客户附件保存于独立私有对象目录。浏览器缓存不作为业务依据。客户和出行人分开建模，一个客户可有多个跟单；跟单与会话一一关联，历史会话保留兼容读取。顾问信息按工作空间和账号强制隔离。商户仅能读取核实单的明确提交内容，不能读取完整客户库、其他供货方案或毛利。

## 应用与事实

有版本的需求账本复用 TripBrief 字段、并发版本及现有报价和目录权限；模型只提出带证据的变更。程序控制采纳、影响、动作与恢复，人工编辑不能被模型覆盖。已发方案和成交记录保存快照，撤销产生新版本，不恢复已吊销的分享。回答、比较及备注引用适用团期的已发布事实及稳定节点编号。测试自动发布内容保留其未人工审核标识。

先试算再形成确认单，客户确认绑定版本。正式报价和分享绑定确认结果、销售价与结算价快照。价格新鲜度、报价展示期限和分享期限分别校验；供应商停售或权限撤销即时生效。线下款项仅为人工登记，不代表平台收款或供应商确认。

## 必须通过的验收

- 两位顾问跨账号读取、修改客户、跟单、附件和成交记录均被拒绝。
- 模糊需求、四国必去、排除与否定、多次改期、人数和混合房型变化均通过多回合真实模型验证。
- 首次找线不自动选线、不提前列团期；已选线后补房型不会退回重新找线；每轮有文字或明确恢复提示。
- 顾问提交核实单，指定商户真实界面接收并回复，顾问重新登录后仍可读取、采纳；其他商户不可读取。
- 通用身份产生一致结算价；修改售价重算利润；亏损报价未经确认不能发布。
- 变更需求、供应商改价或更新行程后，旧方案和确认记录保留但明确失效，不静默复用。
- 线下成交、定金、尾款和供应商订单关联可恢复；不调用上游写接口、不扣库存。
- 客户分享页面只显示对客内容，销售结算差额、私有问答和证件不泄露。
- H5 窄屏、断线重连、刷新与登录恢复通过页面验证。
- ECS 迁移前完成一致备份；迁移和运行角色授权验证后切换；公网两端及多场景、多回合沟通复测通过才标记验收通过。

## 实施状态

已部署到杭州 ECS。数据库为 `0044_advisor_retention`，API 镜像为 `20260927-cp06`，两端网页为 `20260927-cp03`。

顾问与商户的核实闭环、需求变更、多轮答疑、私有材料和恢复检查已通过所列功能验收。真实上游报价仍存在费用、房型未确认的样本，这些样本只能显示已知部分，不能生成正式销售报价。跨顾问隔离在隔离数据库验证；公网使用现有账号完成组织与角色边界检查，没有完成新增第二顾问账号的公网对比。

详细结果与边界见 [ECS 验收记录](advisor-copilot-acceptance.md)。
