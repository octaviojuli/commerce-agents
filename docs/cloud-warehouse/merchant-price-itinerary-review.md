`adultPrice`、`childPrice`、`elderPrice` 均存在于 `priceInfo`。阳光西葡不是儿童、老人字段拼写错误；本次读取的市场价接口返回了零值。不能据此宣称免费，也不能推断同行价格接口的儿童、老人价格同样为零。页面宜显示“上游返回 0，价格待确认”，避免笼统地写成“未提供”。

商户实时观察的连接器只返回市场价。标准结算价区域读取云仓标准价表，但 API 来源未配置这种本地价表，造成结算价空白。客户报价连接器另有 `/order/price` 读取路径，需要 `periodId`、`customerId` 与团期所属部门。

当前来源有效客户映射数量为 0，采购方已确认的映射数量也为 0。因此本次未任意选择客户调用同行报价接口。尚未证明 API 提供独立于采购客户的统一标准结算价。

另一个需要修正的风险是客户报价适配器没有保留、校验 `priceType`。仓库已有接口核查记录指出该接口可能返回不同价格类型。后续必须验证返回类型，再决定显示为同行结算价还是市场价，不能只根据接口名称贴标签。

## 拟调整的刷新流程

每次进入一个 B2B 团期详情，自动发起一次即时查询，显示查询时间与刷新状态。读取结果失败时明确显示失败，旧观察保留原时间，不包装成刚刷新成功。保留手动刷新按钮。普通页面重绘、权限轮询不反复调用上游；切换团期取消旧页面请求，并避免旧结果覆盖新团期。

无采购客户上下文时，先刷新可获取的库存与市场价，同行价明确说明所缺条件；有已确认映射时，才读取对应采购单位价格。统一同行标准价是否另有接口仍需确定。

## 顾问库存边界

建议顾问页面、顾问接口及助手输入统一只提供“有位 / 无位 / 待确认”，库存过期或未获取时为待确认。人数是否满足报价需求可在服务端核验，但不返回库存总数。商户保留具体库存和占位、预留、确认等原始数量。

实施时还需覆盖历史报价卡片、会话恢复和通用团期查询，防止只隐藏页面而接口、助手仍返回余位数字。此项尚未实施。

## 逐日行程草稿

见 `daily-itinerary-preview.html`。虚构 ACME 示例，未导入或发布到业务系统。已有行程结构可以承载本草稿，不需要为了排版另建一套产品模型。

- 线路概览：编号、标题、天数、出发地、产品亮点、简要行程、参考价、图片。
- 每日标题：第几天、城市路线、当天主题。
- 交通：航班、车次或车辆，原文有资料时才显示里程与时长。
- 当天行程：按原文顺序分段；景点显示游览方式、门票是否包含、已知停留时间。没有时间证据时不自动编排时刻。
- 三餐：分别显示内容和已含、不含、待确认。
- 住宿：城市、酒店及标准、是否或同级；夜航、船宿、返家单独表达。
- 费用与规则：包含、不含、购物、自费、儿童及单房差规则、签证、取消与注意事项。
- 来源与复核：原文、附件、真实页码证据、版本与人工修订分别保存。

## 现有 Excel 模板使用

文件：`cloud-warehouse/templates/供应商团期导入模板.xlsx`。现有版本 2，共“填写说明”和“团期导入”两页。每一行代表一个团期，同一条线路通过相同线路编号关联多个团期。

| 字段 | 填写要求 |
|---|---|
| 线路编号、线路名称、天数、出发城市 | 必填；同一线路各行资料一致，编号固定且保存为文本 |
| 团期编号、出发日期、返回日期 | 必填；团期编号唯一，日期格式 YYYY-MM-DD，含首尾天数与天数一致 |
| 总库存 | 必填；表示总容量，不是当前剩余数量 |
| 期初已售、期初停售 | 首次交接必填，零也填写；更新已有团期必须留空，不能覆盖流水 |
| 云仓停售 | 选填“停售”或“解除停售”；空白保留原设置 |
| 云仓报名截止（北京时间） | 选填具体日期时间；空白保留现值，“清空”移除设置 |
| 销售规则说明 | 更改停售或截止规则时必填 |

导入步骤：供应源管理创建或选择 Excel 来源 → Excel 导入下载标准模板 → 替换 ACME 示例数据 → 上传并校验 → 生成变更预览 → 管理员审批发布。采购方可见性另由供采授权控制。

文件最多 5000 行、10 MB；不能修改表头，不支持公式、宏、外部链接。同一线路各行基础资料不能冲突。漏掉某行不会自动删除已发布团期。

当前模板不导入价格矩阵和逐日行程。价格在价格管理中分别维护标准、等级或协议价，行程通过文档上传、解析、复核、审批发布。若需要“一份 Excel 完成产品上架”，应另行设计线路、团期、价格、逐日行程四张关联表并扩展导入器；当前系统不能读取这种新模板。
