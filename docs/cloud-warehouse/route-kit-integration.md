# Route-kit 云仓接入

## 数据边界

新附件使用 `route-kit/1`。`document_parse.body` 保存完整原文单元、引用、整理内容与质量记录；发布内容独立保存。旧 RouteDoc 发布版本按原结构读取。同步和重新解析不覆盖人工修订，不自动发布，也不回写供应商。

| 内容 | 字段 | 规则 |
|---|---|---|
| 每日与节点身份 | `days[].day_id`、`items[].node_id`、`children[].node_id` | 首次由服务端生成，编辑保留 |
| 到访地区 | `days[].countries/cities` | 明确原文依据；出发地、过境机场不作为到访国家 |
| 适用范围 | `applicability.start/end/departure_cities/version_label` | 适用团期校验；有版本范围时全局检索保持未知 |
| 报名规则 | `formation`、`traveler_requirements`、`meeting` | 保存原文引用，缺失不推断 |
| 取消政策 | `cancellation_tiers` | 区间、比例与币种分别保存 |
| 附件价格 | `prices[].category/audience/condition` | 团费、儿童、老人、单房差、服务费、另付费用分开；非实时报价 |
| 航班 | `items[].transport` 的当地时间与跨日数 | 保留参考班次及原文时间表达 |
| 酒店 | `stay.room_type/consecutive_nights/grade_basis` | 供应商酒店描述不自动认定为官方评级 |
| 封面图 | `document_media` 与私有对象存储 | 与解析版本、供应商绑定；凭权限读取，纳入备份与引用保护 |
| 复核 | `route_content_revision.review_resolutions` | 绑定完整内容哈希；修改后重新确认；审核身份留在数据库 |

## 解析与复核

`tour.api.route_kit_worker` 在无凭据子进程中读取文件、解码图片，再由独立模型子进程进行转写和提炼。模型子进程仅接收模型连接配置，不加载数据库、ERP或对象存储凭据。缓存按供应商和连接隔离，Worker 更新租约，超时终止进程组。

商户在独立线路详情中阅读、对照原文、编辑结构化字段、逐项确认、保存草稿，再经原审批中心发布。缺失日序、错误引用、空行程、费用冲突及适用团期冲突不能仅凭勾选消除。机器问题和原文永久保留；人工修复及确认记录在修订版本上。

`route_kit_content` 生成明确列举字段的客户投影。顾问、H5 和模型读取不包含 `units`、`cite`、质量报告或原始来源配置。未知属性不输出，推荐项目明确不含，附件价格与实时团期报价分开。`itinerary_reads` 按概览、日期、条款分页读取，不把截断正文当成完整行程。

共享 `web-shared/route-detail` 渲染新内容，`route-cover` 定期检查封面访问权限。查看完整行程不选择线路，也不加载团期。桌面详情含逐日导航与费用提示，手机显示单栏和日期切换。

未选择团期时，完整行程接口和分节工具提供当前已发布版本的线路参考预览，保留适用范围，并提示尚未核实具体团期。带团期的读取仍按日期、出发地和天数选择适用版本；报价及匹配规则不使用参考预览绕过适用性校验。

## 检索

`route_search_facts` 从已发布、适用的内容派生购物状态、明确含餐数、酒店描述、卖点及自费信息。派生内容保存在现有 `product_search`，与来源、展示、内容和规则版本绑定；索引过期时使用同一份已发布事实回退。空购物列表不证明无购物。价格和库存不进入内容索引。

## 升级

1. 验证新镜像、隔离数据库迁移及新旧附件结果对照。
2. 创建备份，在同 ECS 的隔离数据库完成恢复验证。
3. 停止 API 和所有写入 Worker，迁移至 `0040_route_kit`，刷新运行与认证角色授权。
4. `document.env` 配置模型及 `ROUTE_KIT_ENABLED=true`；对象卷允许文档 Worker 写入派生封面，持久缓存使用独立私有卷。
5. 重启后检查目录范围、库存、历史发布及审批。重新解析只形成新候选稿，人工复核后发布。

模型批量调用须覆盖文字与图片的有效授权。退役旧写入解析器前保留新旧差异报告；旧发布内容、原始附件和历史提取记录继续可读。

## 开发测试模式

默认保持人工审批。指定开发测试部署可显式启用 `route-test-publisher`：仅处理绑定组织与来源的当前解析稿，使用指定操作员身份及原审批事务，发布后记录 `review_mode=test_auto` 与 `quality_metrics`。顾问和商户均显示“测试自动发布 · 未人工审核”。关闭开关即停止新自动发布；历史发布标识不会被改成已人工审核。

门槛为直接引用来源单元数 ÷ 全部来源单元数 ≥85%，不四舍五入后判定，不计推断续句及原样挂入。天数必须完整且匹配，全部行程日整理成功，无遗漏高风险条款、图片读取失败或结构冲突。低于门槛保留草稿和原因，人工编辑后的内容不能用测试通道直接发布。升级涉及 `0041_test_publication`，停止 API 与写入 Worker 后迁移并刷新权限。开发测试环境的备份保留与是否执行恢复演练遵循操作者明确选择；此开关不更改业务库存、订单或上游系统。
