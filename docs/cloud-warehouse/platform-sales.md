# 平台销售模式

销售顾问不必隶属于旅行社。供应商向平台供货，平台已上线产品向所有有效顾问开放，同行结算价统一；未上线线路、停用来源、来源异常隔离的团期及商户私有资料保持不可见。顾问库存仍只展示有位、无位、待确认，订单交易维持关闭。

组织与成员结构继续承担后台权限验证和记录归属。独立顾问开户时创建一个仅本人所属的技术工作空间，不创建旅行社关系、供应商分销授权或 B2B 客户映射。已有工作空间及历史记录保留。平台模式下只有多个历史工作空间的账号显示记录空间切换；它不改变公共货架和统一价格。

## 目录与价格

`0036_platform_sales` 增加离线管理员控制的版本化平台模式，默认关闭以保留其他部署的既有供采授权规则。启用后，`warehouse_buyer_connections()` 对有效顾问返回有效供应商连接；产品、团期、报价方案和已发布文档继续检查当前上架状态及来源隔离。供应商权限保持原样。

API 报价只调用来源的统一价格接口及已配置的标准查询身份，不使用顾问所属工作空间对应的客户映射。Excel 报价只选择有效标准价表，旧等级及协议价不参与；旧配置保留用于历史证据和非平台部署。统一价格未配置时返回缺项，不降级到不同顾问的客户价格。

报价快照使用个人操作人与工作空间共同确定归属及幂等键。平台报价记录模式版本而不伪造分销授权。个人会话、报价及分享不可跨人读取；客户分享继续排除同行结算价。平台开关、供应商可见范围变化会使旧模型上下文不可续接，历史数据库记录保留，重新开启会话使用当前规则。

## 搜索

查询同时保留多个目的地要求，规范空格及加号分隔，识别西葡、法意瑞等有限简称。“西班牙 葡萄牙”可以匹配“西班牙＋葡萄牙”或“西葡”；单独西班牙加其他国家的线路不会满足双目的地要求。附加国家的产品只是候选，助手须明确标为扩展选择。

检索用于找候选产品，不证明实际行程覆盖。酒店、景点、费用和条件仍以已复核内容与实时询价为准。助手必须区分关键词无匹配、所选日期无团期、价格缺项与库存待确认。目录与日期过滤保持权限重查、全局分页和来源版本检查。

客人给出出发月份或日期时，助手先带日期边界筛选线路，再读取相同范围的实际团期。线路结果中的 `departure_date_check` 标识是否执行了日期筛选；未检查日期的候选不能被称为符合客人出行时间。未写年份时依照当前日期判断并说明采用的年份，中旬按 11—20 日查询。查找团期不依赖成人儿童构成与房型，具体询价前再确认这些信息。

## 开通与部署

管理员停止 API 及写入 Worker，备份数据库和私有对象，升级到 `0036_platform_sales` 并刷新 runtime grants，再启动经过测试的新镜像。迁移改变报价唯一键，旧 API 不适合在新结构上处理报价；回退须使用验证过的备份或修复后的兼容镜像。

模式切换使用管理员环境中的 `warehouse platform-sales --enabled true`。顾问开户使用 `warehouse create-advisor --email <email> --password-stdin`，密码从标准输入读取，避免出现在命令参数和日志中。普通 API、顾问和供应商不能切换模式或自行开通账号。登录仍使用平台账号。

行权限沿用项目既有 PostgreSQL 机制，公共目录与个人记录使用不同策略；未关闭 RLS 或让业务服务取得绕过权限。实现参考 [PostgreSQL 行安全策略](https://www.postgresql.org/docs/current/ddl-rowsecurity.html)。
