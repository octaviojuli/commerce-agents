# ADR-010：可溯源的线路字段、适用版本与团期读取

状态：采用。范围为文档内容与查询，不改变库存、报价计算或订单。

## 决策

原生 PDF/DOCX 是文字来源。RouteDoc 3.0 在 1.0、2.0 上新增有默认值的结构字段；旧记录不批量改写，不重算历史哈希。原文行、PDF 物理页、解析代次与文件哈希组成来源证据。来源证据不可由草稿编辑器修改，人工补充字段另记人工修订。

新增字段包括适用范围、成团条件、结构化金额、分段退改、人群和证件限制、保险、集合与联运，以及逐日国家城市、用车、房型连住、航班当地时间和跨日偏移、购物品类。每个新结构对象携带 `raw` 原文和 `source_lines`；不明确的数值、布尔值、日期保持空值。金额使用 Decimal；按人、按间、按晚独立标记，不能用它们推算实时结算价。

## 多版本与团期

发现 A/B 或季节版本、重复的完整天号序列时，保存版本标签和原文行范围，产生 `VARIANTS_DETECTED` 阻断。解析器不会自动拆分或将某一版本默认为全团期适用。

商户人工选定来源版本，整理对应天数，并填写完整适用起止日期及必要的出发城市后，沿原审批流程发布。版本标签必须来自原始版本范围。没有确定年份的“4—6 月版”不能自动推算日期。

不新建可绕过审批的绑定表。已发布文档的 `applicability` 就是版本与团期的关联条件：顾问先选团期，按 `depart_date` 和出发城市在同一已批准来源版本中选择匹配内容。同一范围的新审批版本覆盖旧版本；不匹配时明确“该团期暂无已复核适用行程”。存在范围限定时，未选团期的线路级查询不输出某季节的具体行程。历史无范围限定的文档保持原行为。

关联读取保留产品、团期和供应商的当前行权限，不能通过历史文档编号取得其他来源或未上线产品。匹配只决定行程版本，不改变线路、团期价格和销售状态。

## 一致性与发布

天号、天数、三餐、酒店和正文沿用现有阻断。增加费用包含/不含冲突、封面与逐晚酒店标准冲突、概览与每日三餐冲突、夜宿飞机无航班、住宿晚数不符，以及适用团期实际天数不符。问题指向字段或具体天号；无法判断的差异交人工，不自动修改源事实。

图片少文字页面提示其物理页。原图仍由供应商在私有证据面板核对；人工核对记录与原始检测分开保存，不能通过删改来源标记绕过检查。

## 对客白名单

允许进入客户投影：已审批的适用范围（日期、城市、版本名称）、成团与取消条款、人群证件保险要求、集合和联运、逐日交通住宿、购物与自费、明确对客的服务费与单房差。金额仅为文档条款，必须同时显示单位和原文限制，实时总价仍以报价为准。

不输出：原文行号、解析证据、原文件地址、内部模型报告、审核人、后台标识、采购结算与内部佣金、精确余位。原文未能排除内部结算内容的金额条款不会进入客户投影。缺失不得用默认“已含”“免费”代替。

## 模型与评测

模型抽取只提供与规则并列的候选。每个字段必须通过源行存在和取值核对，规则已有有效值优先；冲突保留规则并提示人工。模型失败或未配置时继续原生流程。模型改写同时检查数字多重集合、条件新增/丢失及对象与数字的关联。复核可显式配置独立模型；未配置时记录使用同一模型的事实，不能宣称独立模型复核。

字段评测使用虚构原文件和人工标注，逐类给出精确率、召回率、缺失与错误；它只覆盖已标注字段，不是全体供应商附件的准确率。私有样本和报告保留在 `.warehouse`。

## 复用与边界

保留当前 Poppler 原生 PDF 和 Word XML 读取路径。参考 [python-docx](https://github.com/python-openxml/python-docx) 的段落与表格结构；[Docling](https://github.com/docling-project/docling) 的结构化文档方向供设计参考，本轮不引入其模型运行栈。购物与另行付费信息完整保留供业务复核，本系统的结构化检查不替代合同及法律审查。
