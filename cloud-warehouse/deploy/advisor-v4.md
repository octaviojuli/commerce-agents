# 顾问 v4 部署

`advisor-v4.compose.yaml` 与 `compose.yaml` 一起使用，增加独立的顾问 API 和网页。
网页默认只绑定宿主机回环端口 18086，API 和数据库没有公网端口。旧顾问网页保持可用，
待新版通过真实云仓、多场景多轮会话验收后，再将 HTTPS 网关切换到新版。

## 数据与凭据

顾问使用独立 PostgreSQL 数据库 `advisor_v4`，角色仅拥有该库，不授予云仓表和云仓
运行角色权限。客户、需求、会话、方案、报价和线下收款记录存放在 `advisor` schema。
云仓目录和结算价格始终通过顾问身份的 HTTP 接口读取。旧顾问记录保留在原库；本部署
不自动转换旧会话，也不把旧报价变成新报价。

将 `advisor-v4.env.example` 的配置保存到私有配置目录的 `advisor-v4.env`，权限 0600。
模型只获得必需的模型配置；顾问进程不装载供应商账号、云仓管理员或云仓数据库凭据。
`ADVISOR_MATERIAL_KEY` 使用独立生成的 32 字节密钥，base64 编码并持久保存。证件目录
`data/advisor-v4-materials` 归 10001:10001 所有、权限 0700，不通过网页静态暴露。
重建容器必须保留数据库、证件文件及密钥；三者与配置共同备份。

## 构建与升级

从同一提交构建经过测试的仓库 API 镜像，再使用 `Dockerfile.advisor-api` 的
`WAREHOUSE_API_IMAGE` 参数构建顾问 API。网页使用 `Dockerfile.advisor-web`，其中
`ADVISOR_API_URL` 在构建时设为 `http://advisor-v4-api:8006`。记录提交、基础镜像 ID 和
产物镜像 ID。运行配置指定 `ADVISOR_V4_API_IMAGE`、`ADVISOR_V4_WEB_IMAGE`。

1. 保存当前镜像、配置和网关文件，生成并校验云仓数据库与私有附件的一致性备份。
2. 停止 API 和写入 Worker，再升级云仓到 `0047_supplier_name_scope` 并刷新 runtime/auth
   授权。迁移 `0045` 需要原有 `WAREHOUSE_ADVISOR_MATERIAL_KEY` 加密旧证件号，不能换新密钥。
3. 核对库存账本、目录数量和同步调度没有被迁移改变，启动升级后的云仓 API 和原有 Worker。
4. 创建独立顾问库及受限角色，启动顾问容器。首次启动在自己的数据库创建 schema。
5. 在回环入口验证登录、独立顾问供应商名称、需求变更、线路检索、问答、报价缺项拦截和
   会话恢复。真实模型与真实供应商数据验收通过后，切换 HTTPS 网关并再次核验。

`/api/health` 检查顾问数据库可读；网页健康检查经过自身代理访问此接口。健康检查不能
代替云仓、模型和业务验收。旧 `/warehouse-api/` 与旧分享入口可继续转发到旧网页以保留
历史记录访问。旧顾问网页本身只连接云仓，不启用旧 ERP 下单接口。

## 回退

新版未达标时保持网关指向旧版；切换后异常则恢复已保存的网关配置。停止新版服务只停止
进程，不删除独立数据库、文件或密钥。恢复旧 API 镜像前检查其与升级后 schema 的兼容性；
`0045` 不能通过解密数据降级。必要时将备份恢复到另一套空库和对象目录，验收后再切换。
禁止覆盖当前业务库或删除数据卷来回退。
